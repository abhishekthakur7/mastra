# Subscription runtime T02 fixtures

This directory is a disposable, package-scoped compatibility harness for the subscription-runtime plan.

- `protocol-fixture` is the only mode implemented here. The MCP server and hook relay bind to loopback and the tool has no network, filesystem, or vendor side effects.
- Generated configuration is deliberately credential-free and disables native tools. It is a harness boundary, not proof of a Claude or Codex model/protocol contract.
- T03's metadata probe is separately controlled: it materializes the exact owned MCP config, executes the profile's strict argv prefix (`--safe-mode --tools "" --strict-mcp-config --mcp-config <owned-file> --setting-sources ""`) before the vendor's version/auth-status commands, and retains only bounded non-secret facts. The harness never reads, returns, or handles credential material; the vendor CLI consults its own subscription state. It preserves the real macOS HOME for vendor Keychain auth, leaves CLAUDE_CONFIG_DIR unset, and never starts a model, tool, hook, or external-effect turn.
- Events are redacted and bounded before recording. Process and workspace resources are tracked by exact path and cleaned with bounded child-process-group termination; hostile descendants that escape their own group are outside this fixture contract, with no raw-PID cleanup fallback.
- Recorder and redactor payloads must be parsed JSON-compatible values: primitives, arrays, and ordinary data objects with no getters, executable accessors, Proxy traps, or other host-language behavior. The redactor's depth, string, array, object-key, and secret-input caps are practical bounds for that data contract; they cannot preempt a hostile in-process Proxy trap.
- Run the offline checks with `pnpm --filter @mastra/mcp test:subscription-runtime` and `pnpm --filter @mastra/mcp typecheck:subscription-runtime`.
- `stdio-server.ts` is only a protocol-fixture entry point. Its launch, handshake, signal/EOF lifecycle, and client-process ownership are T03 boundary work; T02 coverage uses the bounded HTTP fixture instead.
- Cleanup is bounded to children and descendants in the process groups owned by the fixture scope. Metadata probes use the same owned-group SIGTERM→SIGKILL policy, and tests prove a real stubborn descendant is terminated. A hostile descendant that calls `setsid()` or otherwise escapes its group is outside the fixture contract and is prohibited fixture behavior; the harness never falls back to killing a recorded PID.
- `claude-protocol.ts` is an offline-only sanitized JSONL fixture. It incrementally handles UTF-8 chunks, LF/CRLF lines while preserving bare CR content, explicit EOF, bounded total bytes/lines/frames/JSON values, stream/final/structured/error events, and version-bound control-request/response/cancel fixtures. Exact-boundary/max+1 regression checks cover both CRLF terminators and bare-CR content. Validation errors carry the bounded offending line number and received-byte count. Structured output accepts any bounded `JsonValue` (object, array, or scalar); JSON values reject oversized keys/strings and non-finite numbers.
- `ClaudeControlLedger` is an optional bounded state machine for fixture tests. It correlates exact request IDs, rejects duplicate/unknown/late responses and cancellations, normalizes approval (`allow`/`deny`) and interrupt (`cancelled`/`interrupted`/`still_queued`) outcomes, and fails closed for malformed required control responses. It is not evidence that the installed Claude binary uses this wire.
- The protocol command builders use documented CLI switches for stream JSON and explicit session/resume/fork IDs. They include print mode (`-p`) as required by Claude Code's stream-json flags but never append a positional prompt: the host sends exactly one fixed `user` JSONL frame after a validated initialize response. The installed Claude release emits `system/init` after that user dispatch; model stream/final evidence before this post-dispatch marker fails closed. Resume and fork identities are mutually exclusive unless an explicit fork uses distinct source and target IDs. Canonical SDK control responses and the interrupt request omit top-level `session_id`; the live adapter binds an absent response session to the private pending process session and rejects explicit mismatches. Event and control frame shapes are labelled `version-bound-experiment`; cancellation control is not live-tested and must not be treated as a public Claude wire guarantee. `spawnClaudeProtocolProcess` always delegates to `BoundedResourceScope`, so process-group cleanup remains scope-owned.
- `claude-live-wire.ts` and `claude-live-probe.ts` are the opt-in live evidence boundary. T04 covers named start, exact resume, distinct fork, structured output, and cancellation scenarios, each using the version-bound SDK-observed `--max-turns 1` child setting. The strict profile uses `--safe-mode`, so MCP/tools/approvals are intentionally excluded from T04 and reserved for T06/T07. The adapter accepts only bounded candidate frames from the selected release, records bounded markers/counts plus `{wireCode,lineNumber,bytesReceived}` diagnostics, and never replays a dispatched reservation. Unsupported historical frame details are reported only as `protocol-invalid/unsupported-frame`. Live entry uses source-visible opt-in markers only to prevent accidental spawning; the default tests never set them. The no-user compatibility check records the installed executable version while verifying parser behavior without starting a model or sending a user/control frame.
